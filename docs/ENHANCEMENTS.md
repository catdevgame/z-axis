# Enhancements: Aggressive Inline's as the baseline for every game

Aggressive Inline's enhancements are the baseline the other two games get: each one exists in DM2 and BMX XXX as well,
done the way AI's is (its source is in the table), at the game's own functions. Content that exists only because a
release had it (AI's Xbox textures, languages and French speech, the Zoo, Estate, the Ape) is not part of the baseline:
a game gets the like only where one of its own releases has it (DM2's Xbox levels are that). Enhancements that make
sense for one game alone go in "Per game" below.

## When

An enhancement hooks one subsystem of the game (its camera, HUD, pause menu, saves, sound). Port it in a game once that
subsystem's functions are readable and Verified there, alongside the readable work, not before it: the enhancement then
calls named, typed functions rather than addresses, and the gate keeps proving the game unchanged with it off. The app's
settings rows come from the game's options in runtime/src/collection/settings.cpp (profiles()); a ported
enhancement adds its option to the game's profile.

Defaults change no game logic: each enhancement is off, or at the game's own value, until the player picks
it, and logiccheck, dm2logic, bmxlogic and the A/B run with the defaults.

In Aggressive Inline, widescreen, a field of view other than 75 (the Camera page) and mouse-look's turned view change
the random sequence compared with 4:3 play; the game is otherwise the same. Its effects (particles, explosions, blood
splashes) draw from the game's one random number generator as they come into view, so a wider or turned view that
shows one more emitter draws one more number (qa3 F1: Movie Lot, one more particle at script 2,242, the skater apart
from 3,117). The user accepted this: the three settings' help lines and settings.ini / controls.ini comments say so
(GameSettingsProfile::viewChangesRandom, collection/settings.cpp). DM2 and BMX XXX kept the same game with each of them on
qa3's routes.
